# Guía 2.1.2: React + Bootstrap en una instancia EC2 de AWS (con VS Code)

|                                |                                                                    |
| ------------------------------ | ------------------------------------------------------------------ |
| **Asignatura**                 | DSY1104 Desarrollo Full Stack II                                   |
| **Experiencia de aprendizaje** | EA2: Creación y configuración de sitios web                        |
| **Tiempo**                     | 2 h                                                                |
| **Modalidad**                  | Individual                                                         |
| **Indicador de logro**         | IL 1.1                                                             |
| **Requisitos**                 | Computador, VS Code instalado, cuenta de AWS Academy (Learner Lab) |

**Objetivo:** levantar una app React con React-Bootstrap dentro de una instancia EC2, editándola con VS Code conectado por SSH, y verla desde tu navegador usando la IP pública.

> ⚠️ **Cómo leer esta guía:** los recuadros como este marcan cosas que **cambiaron respecto a la versión original** (PDF y apuntes de la EA). Si en clases ves un comando distinto al del PDF, la explicación está en el recuadro.

## Qué cambió respecto a la guía original

| Original                                                            | Ahora                                                       | Por qué                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npx create-react-app .`                                            | `npm create vite@latest` (plantilla React)                  | Create React App está **deprecado** desde febrero de 2025 (ver [aviso oficial de React](https://react.dev/blog/2025/02/14/sunsetting-create-react-app)). Vite es el reemplazo más cercano: mismo flujo (crear, instalar, ejecutar) y React sigue igual.    |
| Node 14 (`nvm install 14`)                                          | Node 22 (`nvm install 22`)                                  | Node 14 hace años que no tiene soporte y Vite exige Node 20.19+ o 22.12+.                                                                                                                                                                                  |
| `sudo yum ...`                                                      | `sudo apt-get ...`                                          | La guía mezclaba `yum` (Amazon Linux) con Ubuntu. En Ubuntu **no existe `yum`**.                                                                                                                                                                           |
| Usuario `ec2-user`                                                  | Usuario `ubuntu`                                            | En Ubuntu el usuario por defecto es `ubuntu`. `ec2-user` es de Amazon Linux.                                                                                                                                                                               |
| Crear y editar archivos con `nano`                                  | Crear y editar archivos con **VS Code** (conectado por SSH) | `nano` es difícil para quien recién empieza (atajos con `Ctrl`, todo a ciegas, sin resaltado de código). Con VS Code editas los archivos de la instancia EC2 como si estuvieran en tu computador, con un editor normal: clic, seleccionar, pegar, guardar. |
| Archivos `.js` con JSX                                              | Archivos `.jsx`                                             | Vite exige `.jsx` cuando el archivo contiene JSX.                                                                                                                                                                                                          |
| `src/index.js`                                                      | `src/main.jsx`                                              | Es el punto de entrada en Vite.                                                                                                                                                                                                                            |
| `npm start`                                                         | `npm run dev`                                               | Vite no trae `start` por defecto.                                                                                                                                                                                                                          |
| `PORT=3000 DANGEROUSLY_DISABLE_HOST_CHECK=true react-scripts start` | `vite --host 0.0.0.0 --port 3000`                           | Esas variables eran exclusivas de Create React App. Dejamos el puerto **3000** para no cambiar la regla del Security Group.                                                                                                                                |

## Parte A: Crear la instancia EC2

> ⚠️ **Actualizado:** la consola de AWS cambia su aspecto con frecuencia. Los nombres de los botones pueden variar un poco; guíate por el nombre de la opción, no por la posición.

1. Ingresa a **AWS Academy** → **Laboratorio de aprendizaje de AWS Academy**.
2. Entra a **Módulos** y presiona **Students**. Se abrirá una pestaña nueva (Vocareum).
3. Presiona **Start Lab**. Espera a que el círculo junto a "AWS" se ponga **verde**, y presiónalo.
4. En la consola, entra a **EC2**.
5. En el panel de EC2, presiona **Instancias** → **Lanzar instancias**.
6. **Nombre y etiquetas:** `reactBootstrap`.
7. **Imagen (AMI):** **Ubuntu Server 22.04 LTS**.

   > ⚠️ **Actualizado:** si en la consola aparece Ubuntu 24.04 como opción por defecto, también sirve; los comandos de esta guía son los mismos.

8. **Tipo de instancia:** `t2.micro`.
9. **Par de claves:** _Crear un nuevo par de claves_.
10. Nombre: `userReact` → **Crear par de claves**. Se descarga `userReact.pem`. **No lo pierdas ni lo muevas de carpeta**, lo vas a necesitar varias veces en esta guía.
11. **Configuraciones de red:** marca **HTTP** y **HTTPS** (además de SSH, que viene marcado).
12. Presiona **Editar** y agrega una regla al grupo de seguridad:
    - Tipo: **TCP personalizado**
    - Puerto: **3000**
    - Origen: **Cualquier lugar (0.0.0.0/0)**

    > ⚠️ **Nota:** abrir a "cualquier lugar" está bien para este laboratorio. En un proyecto real se restringe a tu IP.

13. **Almacenamiento:** cambia a **20 GB**.
14. Presiona **Lanzar instancia**.

✅ **Checkpoint:** debe aparecer un mensaje de éxito con el ID de tu instancia.

---

## Parte B: Probar la conexión SSH

Antes de meter VS Code, hacemos una conexión de prueba desde la terminal. Esto valida que la llave funciona y dice "confío en este servidor" la primera vez, así después VS Code se conecta sin problemas.

15. Vuelve a **EC2 → Instancias**, selecciona `reactBootstrap` y presiona **Conectar**.
16. Ve a la pestaña **Cliente SSH** y copia el comando de ejemplo (el que dice `ssh -i "userReact.pem" ubuntu@ec2-...amazonaws.com`). Guarda también la **IP pública** de la instancia, la vas a usar seguido.
17. Abre una terminal **en la carpeta donde está `userReact.pem`**:
    - **Windows:** PowerShell.
    - **Mac / Linux:** Terminal.

    > ⚠️ **Actualizado:** el PDF original pedía abrir CMD "como administrador". **No es necesario.** Windows 10/11 ya trae el cliente SSH y viene con PowerShell.

18. **Solo Mac / Linux:** protege la llave:
    ```bash
    chmod 400 userReact.pem
    ```
    **Solo Windows (PowerShell)**, si al conectarte sale el error `UNPROTECTED PRIVATE KEY FILE`:
    ```powershell
    icacls userReact.pem /inheritance:r
    icacls userReact.pem /grant:r "$($env:USERNAME):R"
    ```
19. Pega el comando que copiaste y presiona Enter. Cuando pregunte `Are you sure you want to continue connecting?`, escribe `yes`.

✅ **Checkpoint:** el prompt cambia a algo como `ubuntu@ip-172-31-...:~$`. Confirmado que la conexión funciona. Escribe `exit` para salir; de aquí en adelante trabajamos desde VS Code.

## Parte C: Conectar VS Code a la instancia (Remote-SSH)

20. Si no tienes VS Code instalado, descárgalo desde <https://code.visualstudio.com> e instálalo.
21. Abre VS Code. Ve al ícono de **Extensiones** en la barra lateral (o `Ctrl+Shift+X` / `Cmd+Shift+X`).
22. Busca **"Remote - SSH"** (de Microsoft) y presiona **Install**.
23. Abre la **Paleta de comandos**: `Ctrl+Shift+P` (Windows) o `Cmd+Shift+P` (Mac).
24. Escribe y selecciona: **Remote-SSH: Connect to Host...**
25. Selecciona **+ Add New SSH Host...**
26. Pega el mismo comando de conexión que usaste en la Parte B, pero con la **ruta completa** al `.pem` (no solo el nombre del archivo), por ejemplo:
    - **Windows:** `ssh -i "C:\Users\TU-USUARIO\Downloads\userReact.pem" ubuntu@TU-IP-PUBLICA`
    - **Mac:** `ssh -i /Users/TU-USUARIO/Downloads/userReact.pem ubuntu@TU-IP-PUBLICA`

    > ⚠️ **Actualizado:** el original nunca llegaba a usar un editor gráfico. Acá la diferencia es que VS Code necesita la ruta completa al `.pem` porque no se ejecuta desde la carpeta donde está el archivo.

27. Elige dónde guardar esta configuración (la primera opción, tu archivo SSH de usuario, sirve).
28. Vuelve a abrir la Paleta de comandos (`Ctrl+Shift+P` / `Cmd+Shift+P`) → **Remote-SSH: Connect to Host...** → selecciona el host que acabas de agregar (aparece como la IP o el alias).
29. Se abre una ventana nueva de VS Code y empieza a conectarse. La primera vez demora un poco (instala "VS Code Server" en la instancia). Si pregunta el tipo de plataforma del servidor remoto, elige **Linux**.
30. Si aparece un aviso `Do you trust the authors of the files in this folder?`, presiona **Yes, I trust the authors**.

✅ **Checkpoint:** abajo a la izquierda de VS Code dice algo como `SSH: TU-IP-PUBLICA`. Estás conectado a la instancia.

31. Abre una terminal integrada: **Terminal → New Terminal** (o `` Ctrl+` `` / `` Cmd+` ``). Esta terminal corre dentro de la instancia EC2, no en tu computador.

✅ **Checkpoint:** el prompt de esa terminal muestra `ubuntu@ip-172-31-...`.

## Parte D: Preparar el entorno (Node.js)

> Desde aquí, todos los comandos van en la **terminal integrada de VS Code** (la que abriste en el paso 31).

32. Actualiza el sistema:

    ```bash
    sudo apt-get update
    sudo apt-get upgrade -y
    ```

    > ⚠️ **Actualizado:** el PDF original también incluía `sudo yum update -y` y `sudo yum install -y gcc-c++ make`. Eso corresponde a **Amazon Linux**, no a Ubuntu. Ya no se usan.

    Si aparece una pantalla morada pidiendo reiniciar servicios, presiona Enter para aceptar.

33. Instala **nvm** (administrador de versiones de Node):
    ```bash
    curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
    . ~/.nvm/nvm.sh
    ```
34. Instala **Node 22**:

    ```bash
    nvm install 22
    ```

    > ⚠️ **Actualizado:** el original usaba `nvm install 14`. Node 14 está fuera de soporte y Vite no funciona con esa versión.

35. Verifica:
    ```bash
    node --version
    npm --version
    ```

✅ **Checkpoint:** `node --version` muestra `v22.x.x` (debe ser 22.12 o superior). Si muestra otra cosa, ejecuta `nvm use 22`.

## Parte E: Crear el proyecto React

36. Crea el proyecto:

    ```bash
    npm create vite@latest my-ecommerce-app -- --template react
    ```

    > ⚠️ **Actualizado:** el original usaba `npx create-react-app .`. Create React App está deprecado. **Vite** es el reemplazo recomendado por el equipo de React, y la app resultante se escribe igual (mismo React, mismos componentes).

    Si te pregunta `Install with npm and start now?`, responde **No**. Si pregunta por opciones experimentales, elige la opción por defecto.

37. Entra al proyecto e instala las dependencias:
    ```bash
    cd my-ecommerce-app
    npm install
    ```
38. Instala Bootstrap y React-Bootstrap:
    ```bash
    npm install react-bootstrap bootstrap
    ```

✅ **Checkpoint:** en la terminal, `ls` muestra `package.json`, `index.html`, `src`, `node_modules`.

## Parte F: Abrir el proyecto en VS Code

39. Ve a **File → Open Folder...** (o `Ctrl+K Ctrl+O` / `Cmd+K Cmd+O`).
40. Escribe la ruta: `/home/ubuntu/my-ecommerce-app` y presiona **OK**.
41. Si vuelve a preguntar si confías en los autores, presiona **Yes, I trust the authors**.

✅ **Checkpoint:** en el panel **Explorer** (ícono de hojas, arriba a la izquierda) ves la estructura del proyecto:

```
my-ecommerce-app/
├── public/
├── src/
│   ├── assets/
│   ├── App.css
│   ├── App.jsx
│   ├── index.css
│   └── main.jsx
├── index.html
├── package.json
├── vite.config.js
└── README.md
```

> ⚠️ **Actualizado:** en el original la estructura era la de Create React App (`public/index.html`, `src/index.js`, `manifest.json`). En Vite el `index.html` está en la **raíz** del proyecto y el punto de entrada es `src/main.jsx`.

42. En el **Explorer**, sobre la carpeta `src`, haz clic derecho → **New Folder** → escribe `components` y presiona Enter.
43. Con la carpeta `components` seleccionada, crea 4 archivos nuevos (clic derecho → **New File**, o el ícono de "archivo nuevo" que aparece al pasar el mouse sobre `components`):
    - `Navbar.jsx`
    - `ProductList.jsx`
    - `ShoppingCart.jsx`
    - `RegistrationForm.jsx`

    > ⚠️ **Actualizado:** los componentes ahora terminan en **`.jsx`** (antes `.js`). En Vite, un `.js` que contiene JSX da error de compilación.

✅ **Checkpoint:** el Explorer muestra `src/components/` con los 4 archivos, todos vacíos.

## Parte G: Escribir la app

Para cada archivo: haz doble clic en el Explorer para abrirlo, selecciona todo el contenido (`Ctrl+A` / `Cmd+A`) si ya trae algo, bórralo, pega el código de abajo y guarda con `Ctrl+S` / `Cmd+S`.

44. Abre `src/main.jsx` y reemplaza todo por:

    ```jsx
    import { StrictMode } from "react";
    import { createRoot } from "react-dom/client";
    import "bootstrap/dist/css/bootstrap.min.css";
    import App from "./App.jsx";

    createRoot(document.getElementById("root")).render(
      <StrictMode>
        <App />
      </StrictMode>,
    );
    ```

    > ⚠️ **Actualizado:** el original decía "agrega el import al principio de `src/index.js`". Ahora el archivo es `main.jsx`. Además **quitamos `import './index.css'`** a propósito: la plantilla de Vite trae estilos propios (centrado, tema oscuro) que se pelean con Bootstrap.

45. Abre `src/App.jsx` y reemplaza todo por:

    ```jsx
    import { Container, Row, Col } from "react-bootstrap";
    import Navigation from "./components/Navbar";
    import ProductList from "./components/ProductList";
    import ShoppingCart from "./components/ShoppingCart";
    import RegistrationForm from "./components/RegistrationForm";

    function App() {
      return (
        <div className="App">
          <Navigation />
          <Container>
            <Row>
              <Col md={8}>
                <ProductList />
              </Col>
              <Col md={4}>
                <ShoppingCart />
              </Col>
            </Row>
            <Row>
              <Col md={12}>
                <RegistrationForm />
              </Col>
            </Row>
          </Container>
        </div>
      );
    }

    export default App;
    ```

    > ⚠️ **Actualizado:** ya no hace falta `import React from 'react'` en cada archivo (desde React 17 el JSX se transforma solo). Renombramos el import a `Navigation` para no confundirlo con el `Navbar` de react-bootstrap.

46. Abre `src/components/Navbar.jsx` y pega:

    ```jsx
    import { Navbar, Nav, Container } from "react-bootstrap";

    const Navigation = () => {
      return (
        <Navbar bg="light" expand="lg">
          <Container>
            <Navbar.Brand href="#home">Mi Tienda</Navbar.Brand>
            <Navbar.Toggle aria-controls="basic-navbar-nav" />
            <Navbar.Collapse id="basic-navbar-nav">
              <Nav className="me-auto">
                <Nav.Link href="#home">Inicio</Nav.Link>
                <Nav.Link href="#products">Productos</Nav.Link>
                <Nav.Link href="#cart">Carrito</Nav.Link>
                <Nav.Link href="#register">Registro</Nav.Link>
              </Nav>
            </Navbar.Collapse>
          </Container>
        </Navbar>
      );
    };

    export default Navigation;
    ```

47. Abre `src/components/ProductList.jsx` y pega:

    ```jsx
    const ProductList = () => {
      return (
        <div id="products">
          <h2>Lista de Productos</h2>
          {/* Aquí irá la lista de productos */}
        </div>
      );
    };

    export default ProductList;
    ```

48. Abre `src/components/ShoppingCart.jsx` y pega:

    ```jsx
    const ShoppingCart = () => {
      return (
        <div id="cart">
          <h2>Carrito</h2>
          {/* Aquí irá el carrito */}
        </div>
      );
    };

    export default ShoppingCart;
    ```

49. Abre `src/components/RegistrationForm.jsx` y pega:

    ```jsx
    const RegistrationForm = () => {
      return (
        <div id="register">
          <h2>Registro</h2>
          {/* Aquí irá el formulario */}
        </div>
      );
    };

    export default RegistrationForm;
    ```

✅ **Checkpoint:** los 6 archivos están guardados (si un archivo tiene un punto blanco en su pestaña en vez de una X, significa que **no** lo has guardado — presiona `Ctrl+S` / `Cmd+S`).

## Parte H: Preparar la ejecución para que sea accesible desde fuera

Por defecto el servidor de desarrollo escucha solo en `localhost`, es decir, **solo dentro de la instancia**. Hay que decirle que acepte conexiones externas.

50. Abre `package.json` en el Explorer.
51. Busca esta línea dentro de `"scripts"`:

    ```json
    "dev": "vite",
    ```

    y cámbiala por:

    ```json
    "dev": "vite --host 0.0.0.0 --port 3000",
    ```

    Guarda con `Ctrl+S` / `Cmd+S`.

    > ⚠️ **Actualizado:** el original pedía agregar `PORT=3000 DANGEROUSLY_DISABLE_HOST_CHECK=true` al script `start`. Esas variables solo existen en Create React App. En Vite el equivalente es `--host 0.0.0.0` (aceptar conexiones externas) y `--port 3000` (mantener el puerto que abrimos en el Security Group).

52. Verifica que el puerto **3000** está abierto en el grupo de seguridad de tu instancia (EC2 → Instancias → tu instancia → pestaña **Seguridad** → reglas de entrada). Si no está, agrégalo como en el paso 12.

## Parte I: Ejecutar y probar

53. En la terminal integrada de VS Code (si la cerraste, ábrela de nuevo con `` Ctrl+` `` / `` Cmd+` ``), inicia la app:

    ```bash
    npm run dev
    ```

    > ⚠️ **Actualizado:** el original usaba `npm start`. En Vite es `npm run dev`.

    Debe mostrar algo así:

    ```
      VITE v... ready in ... ms
      ➜  Local:   http://localhost:3000/
      ➜  Network: http://172.31.x.x:3000/
    ```

    **Deja esta terminal abierta.** Si la cierras, o cierras la ventana de VS Code, la app se detiene.

54. Busca tu **IP pública**: EC2 → Instancias → tu instancia → _Dirección IPv4 pública_.
55. Abre en tu navegador (en **tu computador**, no en la instancia):
    ```
    http://TU-IP-PUBLICA:3000
    ```
    Usa `http://`, no `https://`.

✅ **Checkpoint final:** ves la barra "Mi Tienda" arriba y los títulos "Lista de Productos", "Carrito" y "Registro". Reduce el ancho de la ventana del navegador: el menú debe colapsar en un botón de hamburguesa (eso es Bootstrap responsivo funcionando).

## Si algo falla

| Síntoma                                                 | Causa probable                                                             | Solución                                                                                                              |
| ------------------------------------------------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `UNPROTECTED PRIVATE KEY FILE`                          | Permisos del `.pem`                                                        | Paso 18                                                                                                               |
| `Permission denied (publickey)`                         | Usuario o llave incorrectos                                                | Usa `ubuntu@...` (no `ec2-user`) y el `.pem` correcto                                                                 |
| VS Code se queda pegado en "Downloading VS Code Server" | Conexión lenta o instancia recién iniciada                                 | Espera un poco más; si pasan varios minutos, cierra la ventana e intenta de nuevo con **Remote-SSH: Connect to Host** |
| VS Code pide contraseña en vez de conectar solo         | La ruta al `.pem` en el host configurado está mal escrita                  | Revisa el paso 26; en Windows usa `\` y comillas si la ruta tiene espacios                                            |
| `command not found: yum`                                | Estás en Ubuntu                                                            | Usa `apt-get` (paso 32)                                                                                               |
| Error de Vite o `npm` sobre versión de Node             | Node muy antiguo                                                           | `nvm install 22` y `nvm use 22`                                                                                       |
| Un componente no aparece o tira error de import         | El archivo quedó con extensión `.js` en vez de `.jsx`                      | Bórralo y créalo de nuevo con `.jsx` desde el Explorer                                                                |
| El navegador queda cargando y no responde               | Puerto 3000 cerrado en el Security Group                                   | Paso 12 / 52                                                                                                          |
| `Connection refused`                                    | La app no está corriendo, o falta `--host`                                 | Paso 51 y 53                                                                                                          |
| `Blocked request. This host is not allowed`             | Entraste con el nombre DNS de AWS (`ec2-...amazonaws.com`) en vez de la IP | Entra con la IP, o en `vite.config.js` agrega `server: { allowedHosts: true }`                                        |
| La IP cambió                                            | Al reiniciar el laboratorio la IP pública cambia                           | Copia la IP nueva y actualiza el host en VS Code (`Remote-SSH: Connect to Host` → edita la config)                    |
| Pantalla centrada y oscura, sin estilos de Bootstrap    | Quedó `import './index.css'` en `main.jsx`                                 | Quítalo (paso 44)                                                                                                     |

> ⚠️ **Sobre el Learner Lab:** al terminar tu sesión presiona **End Lab**. Las instancias se detienen y **la IP pública cambia** cuando vuelves a iniciar el laboratorio (vas a necesitar reconectar VS Code con la IP nueva).

## Opcional: llevar la app a "producción" con Nginx

> ⚠️ **Actualizado:** el original solo dejaba una nota diciendo que "para producción se recomienda construir la app y servirla con Nginx", sin pasos. `npm run dev` es un servidor de **desarrollo**; para publicar se genera la versión optimizada y se sirve como archivos estáticos.

1. Detén el servidor de desarrollo con `Ctrl+C` en la terminal de VS Code.
2. Genera la versión de producción (crea la carpeta `dist/`):
   ```bash
   npm run build
   ```
3. Instala Nginx:
   ```bash
   sudo apt-get install -y nginx
   ```
4. Copia la app al directorio que sirve Nginx:
   ```bash
   sudo rm -rf /var/www/html/*
   sudo cp -r dist/* /var/www/html/
   ```
5. Abre en el navegador (ahora **sin puerto**, usa el 80 que abriste en el paso 11):
   ```
   http://TU-IP-PUBLICA
   ```

✅ **Checkpoint:** ves la misma app, pero ahora servida por Nginx y sin necesidad de dejar una terminal abierta.
